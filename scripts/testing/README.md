# 测试治理脚本（testing）

放**不被 CI 直接调用**的测试治理脚本（判据见 bms《测试规范》14.2：会被流水线执行才留平台仓）。

| 脚本 | 用途 |
| --- | --- |
| `测试库改造台账.py` | 按 A~E 判据给两仓测试文件定档，产出台账 md + json（任务 04-6-2） |

## 测试库改造台账

背景：测试体系改为「每逻辑数据源一套库 + 用例叠加」后，存量用例要分层处置（A 不动 / B 机械改造 / C 语义重写 / D 白名单 / E 删除）。定档由脚本产出，人工只复核结论。

```bash
# 在任意目录执行（工作区根按脚本位置推导：<工作区>/test/scripts/testing/）
python test/scripts/testing/测试库改造台账.py                 # 只打印台账
python test/scripts/testing/测试库改造台账.py --out <目录>     # 写 md + json 到目录
python test/scripts/testing/测试库改造台账.py --check <json>   # 对账：列出与台账不一致的文件
```

判据优先级 **E > D > C > B > A**：

- **E**：顶层 `import` 指向的仓内模块已不存在（功能删除候选，需人工确认后再删并核覆盖率）
- **D**：「建库即被测」——已打 `own_db` 白名单，或命中建库 / 迁移 / 多库拓扑 / 每租户派生库特征
- **C**：自建库痕迹 **且** 含整表断言（`len(...) == N`、`total == N`、`count()` 比较）
- **B**：自建库痕迹，无整表断言
- **A**：无自建库痕迹（纯逻辑 / 契约 / 路由 / 静态护栏）

`--check` 以台账 json 为基线：新文件、类别漂移、已删除文件都会列出来，收口时用它证明「台账与代码一致」。

注意：脚本只做扫描与报告，**不改代码**——改写由人工按《04-6-2 详细设计》§6 的模板执行后，重新生成台账即可。
