# test 仓库（测试资产）

> 测试资产的独立仓库 · 平台机制的测试部分不放在这里

## 1. 定位

本仓库承载**测试资产**（用例模板、测试数据、压测场景、探索性测试记录、测试侧工具脚本），
与平台/产品仓库**平级并置**，各自独立版本管理：

| 仓库 | 承载 | 文档根 |
| --- | --- | --- |
| `bms/` | BMS 平台机制、通用基座、CI 流水线 | `bms文档/` |
| `biz/` | biz 产品专属内容 | `biz文档/` |
| **`test/`（本仓库）** | **测试资产** | **`test文档/`** |

> 分工红线：**bms 不关心测试资产**。被流水线直接调用的脚本（`check-base.py`、`check-status.py`、`defect/*`、`governance/*`）留在 `bms/scripts/tools/`——迁移出去会让 CI 多克隆一个仓库。本仓库只放**不被 CI 依赖**的测试资产。

## 2. 目录结构

```text
test/
├── README.md           # 本文件
├── test文档/            # 测试文档（详见 test文档/文档首页.md）
│   ├── 文档首页.md      # 测试文档导航
│   └── 资产总览.md      # 五类测试资产落点与边界（权威表）
├── scripts/            # 测试侧脚本（详见 scripts/README.md）
│   ├── kiwi/           # Kiwi 用例登记 / 维护 / 导出
│   ├── perf/           # 压测场景 scenario_*.py
│   └── data/           # 测试数据生成与环境准备
└── bms文档 -> ../bms/bms文档   # 基座软链（不入库，引用平台规范用）
```

递归引用方式（与产品仓同口径）：本仓文档引用平台规范写 `../bms文档/规范/测试规范.md`。

## 3. 软链约定（不入 git）

| 位置 | 软链 | 作用 |
| --- | --- | --- |
| `bms/test文档 → ../test/test文档` | bms 仓**根**，与 `bms文档/` 同级 | 平台侧导航到测试资产（仅本地/工作区可见） |
| `test/bms文档 → ../bms/bms文档` | test 仓**根**，与 `test文档/` 同级 | 测试侧引用平台规范 |

- 两侧软链**都不入库**：bms 侧已写入 `bms/.gitignore`（`test文档`），本仓 `.gitignore` 忽略 `bms文档`。目的是防止误 `git add` / `git clean` 损坏，并保持仓库互不污染。
- 副作用须知：**bms 文档正文不要写真链接指向测试文档**——CI 只 clone bms，软链目标不存在时会被 `check-base` 判断链；需要提及时写纯文本路径。
- Windows 克隆与 GitLab 网页端不可用此软链，文档工作区以 Linux 为准。

## 4. 加入工作区

1. 在工作区根并置克隆本仓库（`git clone <远端> test`）。
2. 建双向软链：

    ```bash
    cd test && ln -sfn ../bms/bms文档 bms文档      # 本仓引用平台规范
    cd ../bms && ln -sfn ../test/test文档 test文档  # 平台侧导航到测试资产
    ```

3. 在 `*.code-workspace` 的 `folders` 增加 `{ "path": "test", "name": "测试资产" }`。

> 依《文档生成规范》编写 · 测试资产仓库
