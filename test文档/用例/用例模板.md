# 用例模板

> Kiwi 用例的编写模板与登记口径 · 与 `scripts/kiwi/register_cases.py` 配套

## 1. 用途

本模板是**资产侧的填写规范**，方法类口径（分层、命名、覆盖率、缺陷流程）见平台
《[测试规范](../../bms文档/规范/测试规范.md)》，此处不重复。登记走
`scripts/kiwi/register_cases.py`（按 `summary` 去重、回读平台编号）。

## 2. 字段模板（对应 JSON 输入）

```json
{
  "product": "BMS 基础管理系统",
  "cases": [
    {
      "summary": "<域>-<序号>-<标题>：<场景>（<关键操作>）",
      "text": "<p><strong>前置</strong>…</p><ol><li>步骤</li></ol><p><strong>预期</strong>…</p>",
      "category": "平台骨架",
      "priority": "P2",
      "status": "CONFIRMED",
      "author": "admin",
      "tags": ["自动化"],
      "is_automated": true
    }
  ]
}
```

| 字段 | 取值与约定 | 常见坑 |
| --- | --- | --- |
| `summary` | **平台内按此去重**，也是自动用例匹配键；格式 `<域>-<序号>-<标题>` | 自动用例的 summary 是 pytest nodeid，策展用例别与之撞名 |
| `text` | HTML：前置 → 步骤（有序列表）→ 预期 | 纯文本换行在平台上会挤成一段 |
| `category` | 平台骨架（策展库）；缺省回落到产品首个分类 | 分类与产品绑定，跨产品不可用同一个 |
| `priority` | P1~P5，平台骨架用 P2 | 用 `value`（P2）不是显示名 |
| `status` | CONFIRMED | 草稿态不计入执行统计 |
| `tags` | 自动化用例加「自动化」 | 标签按需创建，不预设 |
| `is_automated` | 有对应用例代码置 true | 与 `tags` 是两套东西，别只加标签 |

## 3. 与代码的关联 <a id="linkcode"></a>

**双轨标注**（两侧都要写平台回读编号）：

| 侧 | 标注形式 | 示例 |
| --- | --- | --- |
| 后端（pytest） | `@pytest.mark.kiwi_id(<编号>)` 装饰器 | `@pytest.mark.kiwi_id(529)` |
| 前端（Vitest） | `describe('<主题>（Kiwi <编号>）')` 用例名内标注（前端仓库约定） | `describe('根系基类（Kiwi 698）', () => {…})` |

两侧一致性由 `scripts/kiwi/export_cases.py --reconcile --code-root <代码根>` 定期核对（输出
`matched` / `only_code` / `only_platform` 三类）。**注意当前对账只扫 `**/*.py`**：
前端的 `describe` 标记扫不到（前端引用需手工核对），且 `only_code` 会含 CI 自动用例产品中的编号（假阳性）——
两处口径缺口见 `scripts/kiwi/README.md` 第 2.2 节与《[Kiwi 用例台账](Kiwi用例台账.md)》§6 待办。

**编号以平台回读为准**：编号全局自增且跨产品共享（自动用例产品会占号），新登记用例实际编号会跳号——
登记后取脚本回读的 `case_id` 回填代码标记，不要假设「上一号 + 1」。

## 4. 填写检查清单

- □ 标题含场景与关键操作，能独立看懂（不依赖上下文）
- □ 前置写明环境与数据；步骤可执行；预期可判定（有具体值/状态）
- □ 已确定分层（单测 / 接口 / 集成 / E2E）与是否自动化
- □ 与现有用例不重复（登记前先在 Kiwi 搜标题；脚本也会按 summary 去重跳过）
- □ 登记后：回读编号 → 回填代码 `kiwi_id` → 纳入下一次对账
