# 探索性测试记录模板

> 时间盒驱动的探索性测试（SBTM）会话记录 · 一份会话一份记录

## 1. 与脚本化用例的分工

- **脚本化用例**（Kiwi）：可重复、可自动化，回归执行。
- **探索性测试**（本模板）：靠人的判断发现**用例没覆盖到**的问题；不追求可重复，但要求**可追溯**。
  会话中若发现值得长期守护的场景，应回写为 Kiwi 用例（走《[用例模板](用例模板.md)》）。

## 2. 会话章程（会话开始前填写）

```text
会话编号：ET-<日期>-<序号>
目标（ charter ）：本次要探索什么？要回答什么问题？
范围：涉及的模块 / 接口 / 页面
不测什么：明确排除（避免跑偏）
时间盒：__ 分钟（建议 60~90，不可延长；需要更多时间就开新会话）
环境：分支 / commit / 依赖服务状态
执行人：
```

## 4. 发现与缺陷

| # | 现象 | 严重度 | 平台 | 处理 |
| --- | --- | --- | --- | --- |

- 分级与建单流程见平台《[测试规范](../../bms文档/规范/测试规范.md)》§9「缺陷管理」。

## 5. 会话收尾

```text
实际用时：__ 分钟（对比时间盒，超时说明目标切得太大）
覆盖区域（打了哪些点，哪些没打）：
发现的缺陷数（按级别）：P0 __ / P1 __ / P2 __ / P3 __
值得转成 Kiwi 用例的场景：（转写后回填用例编号）
遗留疑问 / 下次 charter 建议：
结论：□ 可进入下一区域　□ 该区域风险仍高，建议补充会话
```

## 6. 归档

记录落本目录 `test文档/用例/`，命名 `ET-<日期>-<序号>.md`；缺陷以 GitLab Issue 为准，本记录只留编号与结论。
