# Kiwi 用例台账

> 平台策展用例的批次台账与对账留痕 · 用例本体在 Kiwi TCMS，不在 git

## 1. 口径 <a id="rule"></a>

- **两个产品分开看**：`BMS 基础管理系统` 承载**策展用例**（人工设计、一任务一条，含编号）；`BMS 自动化用例（CI）` 是 CI 导入的执行记录（一函数一条，数量大、编号连片）——**本台账只记策展用例**。
- **编号是平台全局自增且跨产品共享**：策展用例编号必然跳号，登记后以 `scripts/kiwi/register_cases.py` 回读的 `case_id` 为准（实证：策展第 70 条为 528，阶段四首条为 698）。
- **本台账不复制用例正文**（正文在平台，含步骤与预期），只记「批次 / 范围 / 编号 / 状态 / 对账」；需要正文时用 `export_cases.py` 导出或用平台网页查。
- 状态语义：`CONFIRMED` = 现行有效；`DISABLED` = 已停用（保留编号与历史，不复用）。
- 数据来源：`scripts/kiwi/exports/` 下的平台快照 + 各批次登记输入（`scripts/kiwi/cases/`）。

## 5. 新增批次维护流程 <a id="flow"></a>

1. **先登记、后编码**（《测试规范》「用例管理（Kiwi TCMS）」节）：按 `examples/cases.example.json` 写输入文件，落在 `scripts/kiwi/cases/<日期>_<任务>_<名称>.json`。
2. `--dry-run` 自查容器内将执行的代码，再正式登记并**回读实际编号**（跳号属正常）。
3. 代码侧以平台编号标注：后端 `@pytest.mark.kiwi_id(N)`；前端 Vitest 用 `describe('…（Kiwi N）')`（前端仓库约定）。
4. 回填两处文档：bms 任务 `测试/NN_测试_xx.md`（用例表 + 结论）与本台账（§2 追加批次、§3 更新为最新批次）。
5. 需要留痕时用 `export_cases.py --out exports/<日期>_策展用例快照.json` 存平台快照（口径见 `scripts/kiwi/exports/README.md`）。
