# 阶段测试报告模板

> 阶段末测试报告（`项目/<阶段>/NN_测试报告_<阶段>.md`）的结构骨架与字段口径 · 依据《[测试规范](../../bms文档/规范/测试规范.md)》「测试报告」节

## 1. 用途与落点 <a id="purpose"></a>

- **报告属项目文档，不入本仓**：落点 `bms文档/项目/<阶段>/NN_测试报告_<阶段>.md`，阶段末输出一次（《测试规范》§12）。
- 实例参照：`bms文档/项目/03_后端插件化/01_测试报告_后端插件化.md`（阶段三）。
- 要素（规范 §12）：用例执行统计、缺陷统计、覆盖率、风险与遗留项；阶段末含**经验教训（复盘）**；MVP 验收前另有总测试报告。
- 数据来源三类：本地门禁命令快照、GitLab 流水线、Kiwi TCMS 平台——**全部贴原始输出**（附录 A），正文只给结论与去向。

## 3. 字段口径与常见坑 <a id="fields"></a>

| 字段 | 口径 | 常见坑 |
| --- | --- | --- |
| 阶段范围 / 任务 | 与阶段需求总览、计划的状态口径**逐字一致**（条数、工时） | 报告与需求 / 计划的状态不一致，收口核对会失败 |
| 用例执行统计 | 分层次给（后端 / 契约 / 前端 / E2E / 文档断言），跳过项写清原因 | 只给一个总数，掩盖跳过与未激活层次 |
| Kiwi 新增编号 | 只列**本阶段新增**的策展编号，按域分组 | 把历史编号算进来，与台账 §2 对不上 |
| 缺陷统计 | 自动捕获与人工上报分列；过程问题不算缺陷但要有落点 | 把实施返工算成产品缺陷 |
| 风险与遗留 | 每条给「影响 + 去向」，转出的写归口阶段 / 任务号 | 写「后续关注」而无归口 |
| 复盘 | 写**已发生的事实**与**已固化的动作**，不写口号 | 泛泛「加强测试」，无法验收 |
| 附录 A | 命令可直接重跑；输出含用例数、覆盖率、流水线号、缺陷查询结果 | 手抄数字、不贴原始输出 |

## 4. 填写检查清单 <a id="checklist"></a>

- □ 头部 meta 表与阶段需求 / 计划状态逐项一致（条数、工时、完成情况）
- □ 用例执行统计分层给全，跳过 / 未激活层次写明原因
- □ Kiwi 新增编号与《[Kiwi 用例台账](../用例/Kiwi用例台账.md)》批次记录一致
- □ 缺陷统计区分自动捕获与人工上报，过程问题有落点
- □ 覆盖率给「全量 + 新增 / 核心」两个口径，未覆盖行有说明
- □ 风险与遗留逐条有影响与去向（归口阶段 / 任务编号）
- □ 复盘写事实与固化动作；附录 A 命令可重跑
- □ 提交前跑 `check-links`（`项目/` 内相对层级易错）
