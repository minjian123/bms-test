# 缺陷单模板

> GitLab Issue（缺陷）的填写骨架与现场数据口径 · 依据《[测试规范](../../bms文档/规范/测试规范.md)》「缺陷管理」节

## 1. 用途与两条上报路径 <a id="purpose"></a>

缺陷载体是 **GitLab Issue + Milestone**（按阶段 / 版本关联），Kiwi TCMS 平台的缺陷链接指向对应 Issue（《测试规范》§9）。两条上报路径：

| 路径 | 触发 | 谁建单 | 现场包 |
| --- | --- | --- | --- |
| 自动上报 | MR / main 流水线任一自动化测试失败 | `bms/scripts/tools/defect/defect_capture.py` 按「用例 ID + 失败摘要」指纹查重后自动建单（打 `defect-auto` 标签），已存在则追加评论 | REPRO 复现包：`现场 dump + stacktrace.txt + repro.json + REPRO.md`，归档 mjbk `/mnt/data/backup/defects/<缺陷号>/` |
| 人工上报 | UAT、探索性测试、用户反馈 | 用本模板建单（或按 `defect_capture.py --summary` 手动执行生成模板后补填） | P0 / P1 **必须**附问题现场 dump；P2 / P3 视可复现性可选 |

- **定级与指派由人做**：自动单建好后需人工补充复现步骤并定级（P0 ~ P3），再进指派修复；CI 只负责回归验证，合入与关闭由人执行（AI 辅助修复同样不自动合入 / 关闭）。
- **dump 含业务数据，不入 Git**：随每日备份在 mjbk 保留 30 天；文档只写路径与编号。

## 2. 缺陷单骨架 <a id="skeleton"></a>

> 骨架代码块内的 `<…>` 占位不是有效链接（复制后替换即解析），属预期。

**标题**（模板默认约定，可按项目调整）：`[P<级别>][<模块>] <现象一句话>（<失败用例名 / 关键接口>）`

```markdown
## 概要

<一句话说清：在什么入口做什么操作，出现什么错误结果，期望是什么。>

## 分级与影响

- 分级：P<0~3>（P0 阻断主流程 / 数据安全；P1 严重功能缺失 / 可用性降级；P2 一般缺陷；P3 轻微 / 建议）
- 影响范围：<受影响租户 / 角色 / 模块 / 数据>
- 是否阻断：<阻断 MR 合入（P0 / P1）/ 不阻断>

## 复现步骤

1. <前置：环境、账号、数据准备（写明数据集或造数入口）>
2. <操作步骤，逐步可执行>
3. <操作步骤>

**期望结果**：<可判定的具体值 / 状态>
**实际结果**：<实际值 / 状态，附关键日志片段（脱敏）>

## 复现环境

| 项 | 值 |
| --- | --- |
| 代码版本 | commit `<短哈希>`（分支 `<分支名>`） |
| 关联用例 | Kiwi `<编号>`；自动化文件 `<测试文件>::<用例名>`（无则写「人工」） |
| 运行环境 | <环境标记：dev / test / 专用环境；数据库与关键依赖版本> |
| 流水线 | <流水线编号与地址（自动上报路径填）> |

## 现场数据

- 归档路径：`/mnt/data/backup/defects/<缺陷号>/`（P0 / P1 必附 dump；命令见对应数据库部署说明「日常运维」节）
- 包内清单：`dump.sql`（或 `dump.dmp`）/ `stacktrace.txt` / `repro.json` / `REPRO.md`
- 脱敏说明：<是否已脱敏、脱敏范围>

## 处置

- 修复分支 / MR：<链接>
- 回归方式：按「代码 commit + 用例 + dump 导入」重建现场（`reproduce.py --issue-repro <复现包目录> --dump-target <库>`）
- 关闭条件：<回归通过 + 无回归；关联 Kiwi 用例执行结果已更新>
```

## 3. 字段口径与常见坑 <a id="fields"></a>

| 字段 | 口径 | 常见坑 |
| --- | --- | --- |
| 标题 | 级别 + 模块 + 现象，**不写解法** | 标题写成「XX 需要优化」，无法判定关闭条件 |
| 分级 | 按《测试规范》§9 四条判据（阻断主流程 / 数据安全 → P0；严重缺失 → P1） | 全填 P0，失去分级意义 |
| 复现步骤 | 前置 + 步骤 + 期望 + 实际，四段齐；步骤可照做 | 只说「偶尔失败」而无数据与环境 |
| 关联用例 | 写 Kiwi 编号与 `文件::用例名`，两处都要 | 只写文件名，回归时定位不到用例 |
| 现场数据 | P0 / P1 必附 dump 并写归档路径；文档只写路径不贴 dump 内容 | 把 dump 直接贴进 Issue（含业务数据、泄露） |
| 关闭条件 | 回归方式写明（重建现场 + 用例通过 + 无回归） | 关闭时只写「已修复」，无回归证据 |

## 4. 检查清单 <a id="checklist"></a>

- □ 标题含级别、模块与现象，能独立看懂
- □ 分级有依据（对照《测试规范》§9 判据），并说明是否阻断合入
- □ 复现步骤四段齐（前置 / 步骤 / 期望 / 实际），关键日志已脱敏
- □ 复现环境写全（commit、用例编号、环境标记、依赖版本）
- □ P0 / P1 已导出 dump 并写入 `/mnt/data/backup/defects/<缺陷号>/`
- □ 关联 Kiwi 用例与自动化文件::用例名
- □ 关闭条件含回归方式与证据要求

> 依《文档生成规范》编写 · 测试资产仓库
