# 测试资产总览

> 五类测试资产的落点、归属与迁移边界（权威边界表）

## 1. 目的与适用范围 <a id="purpose"></a>

测试相关的东西分散在**五个地方**，本表是唯一权威索引：新增测试资产前先查这里，
避免把资产放错仓库（尤其不要把测试资产塞进 `bms`，也不要把被 CI 依赖的脚本迁出 `bms`）。

## 2. 资产落点表 <a id="map"></a>

| 类别 | 落点 | 归属 | 说明 |
| --- | --- | --- | --- |
| 测试方法 / 规范 | `bms/bms文档/规范/测试规范.md`、`bms/bms文档/设计/架构设计/32_架构设计_测试与质量.md` | **bms 平台** | 分层、命名、覆盖率、缺陷、结果导入等口径；本仓不重复 |
| 用例本体 | Kiwi TCMS（外部系统，不在 git） | 平台 | 代码侧用 `@pytest.mark.kiwi_id(N)` 关联；结果导入见《测试规范》§12 |
| 测试代码 | `bms/backend/tests/`、前端 `*.(test|spec).ts` | 各工程内 | 单测随代码走，由 MR / main 流水线执行 |
| 测试记录与报告 | 项目任务目录 `测试/NN_测试_xx.md`、阶段 `测试报告_<阶段>.md` | **产品/项目文档** | 随项目归档，不入本仓 |
| **测试资产（本仓）** | `test/test文档/`、`test/scripts/` | **本仓** | 用例模板、Kiwi 维护脚本、压测场景、测试数据、探索性测试记录 |

## 3. 迁移边界（什么不该进来）<a id="boundary"></a>

以下脚本**被流水线直接调用，留在 `bms/scripts/tools/`**——迁出会让 CI 多一次跨仓克隆：

| 脚本 | 为什么不能迁 |
| --- | --- |
| `check-base.py`（基座自检） | `base-integrity` job 直接跑 |
| `check-status.py`（文档状态核对） | 同上 job 串行执行 |
| `defect/defect_capture.py`、`ai_fix.py`、`reproduce.py` | 流水线失败时自动上报，须随 bms 拉取 |
| `governance/collect_metrics.py`、`review_stage.py` | 阶段度量与复盘，依赖 bms 项目文档树 |

判据很简单：**会不会被 CI 直接 `python3` 调用？会 → 留 bms；不会 → 本仓。**
